<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Host → Inbox API | `mark_read/3` and `mark_seen/3` accept `notification_id` + `recipient_identity` from host; scoped update prevents cross-recipient mutation. |
| Inbox → Signal layer | `tenant_id` resolved from durable child rows on same notification — never from caller args. |
| Signal → operator traces | Payload includes `notification_id` in signal row; transition context unchanged (event name only). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-49-01 | Spoofing / Elevation | cross-tenant signal emission | mitigate | `resolve_tenant_id/1` reads `WorkflowRun.tenant_id` or `Delivery.tenant_id` for the notification — never accepts tenant from `mark_read` args. Skip emission when nil. |
| T-49-02 | Spoofing | cross-recipient mark + signal | mitigate | Existing `recipient_identity` scope on `update_all`; `actor_id` on `Signal.track` equals `recipient_identity`. |
| T-49-03 | Denial of Service | signal flood on re-mark | mitigate | D-06 first-transition `is_nil(field)` guard — re-mark returns `:ok` without second `Signal.track`. |
| T-49-04 | Information Disclosure | payload in operator traces | accept | `route_signal/1` unchanged — context is `%{"event_name" => event_name}` only (D-08). |
| T-49-05 | Tampering | forged notification_id in payload | mitigate | Payload is system-generated from the updated notification row, not caller-supplied. |

**No `high`-severity threats.** Tenant resolution is the only new surface; mitigation is skip-not-forge. Block condition not triggered.
</threat_model>
