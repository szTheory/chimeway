# Milestone v1.1: Production Trust

**Status:** ✅ SHIPPED 2026-04-27
**Phases:** 13-16
**Total Plans:** 18

## Overview

Chimeway v1.1 delivered the production-trust baseline: explicit policy and preference controls, durable retry and final-state convergence, safe end-to-end observability, and documented integration seams for host applications.

## Phases

### Phase 13: Policy & Preference Maturity

**Goal**: Make suppression and preference behavior explicit so product teams can trust delivery decisions.
**Depends on**: Phase 12
**Plans**: 3 plans

Plans:

- [x] 13-01: Add category preference storage and lookup APIs
- [x] 13-02: Add quiet-hours and delivery-cap policy settings
- [x] 13-03: Wire policy evaluation and suppression enforcement

**Details:**
Category preferences, quiet-hours, and delivery-cap settings are now persisted as first-class data. Policy evaluation reads persisted preference and settings state before enqueue and before perform, records explainable suppression reasons, and keeps runtime input string-safe.

### Phase 14: Delivery Reliability Hardening

**Goal**: Make delivery retries and duplicate protection safe under real-world concurrency and failure.
**Depends on**: Phase 13
**Plans**: 11 plans

Plans:

- [x] 14-01: Wave 0 scaffold reliability test files
- [x] 14-02: Migration plus DeliveryAttempt schema (`attempt_number`, `error_class`)
- [x] 14-03: Promote `terminal_states/0` and add `Deliveries.exhaust_delivery/1`
- [x] 14-04: Executor classification plumbing and sync convergence
- [x] 14-05: Oban retry contract and trace field surfacing
- [x] 14-06: REL-01 duplicate protection tests
- [x] 14-07: REL-02 and REL-03 attempt history, retry exhaustion, terminal convergence tests
- [x] 14-08: REL test convergence and regression spot-checks
- [x] 14-09: Gap closure for stale-struct lock fix and genuine concurrency test
- [x] 14-10: Gap closure for catch-all convergence hardening

**Details:**
Delivery attempts now preserve `attempt_number` and `error_class`, duplicate protection and retry behavior are covered by reliability-focused tests, terminal states converge durably across sync and Oban paths, and concurrency edge cases are locked down with targeted regressions.

### Phase 15: Observability & Supportability

**Goal**: Make every lifecycle step traceable without exposing sensitive payload data.
**Depends on**: Phase 14

**Details:**
Trace queries now accept downstream Ecto options so host applications can preserve tenancy boundaries, and telemetry verification confirms correlation metadata remains available without leaking payload fields.

### Phase 16: Integration Hardening

**Goal**: Make host-app adoption easier and safer through clear setup and stable seams.
**Depends on**: Phase 15
**Plans**: 3 plans

Plans:

- [x] 16-01: Expand installation and getting-started documentation
- [x] 16-02: Expand Oban async dispatch and telemetry tracing recipes
- [x] 16-03: Harden the custom adapter guide for runtime safety

**Details:**
The integration path is now documented end to end: installation, getting started, transactional Oban dispatch, safe telemetry tracing, and custom adapter authoring. Documentation was backed by a small code improvement to support the idiomatic `use Chimeway.Notifier` path.

## Milestone Summary

**Key Decisions**

- Keep policy suppression explainable at both planning-time and perform-time.
- Preserve delivery-attempt history as durable product behavior, not transient retry state.
- Treat telemetry redaction and correlation as operator-surface requirements, not optional diagnostics.
- Tighten integration seams through documentation and contract-tested runtime safety rather than framework magic.

**Issues Resolved**

- Preference and policy behavior moved from implicit expectations to explicit persisted controls.
- Retry exhaustion, duplicate protection, and terminal convergence now land in durable final states.
- Trace queries can respect host tenancy boundaries while retaining explainable lifecycle correlation.
- Host applications have a documented and safer path for installation, async dispatch, tracing, and custom adapters.

**Issues Deferred**

- No open milestone gaps were carried forward at close.

**Technical Debt**

- Next milestone scope remains undefined; deferred v2 requirements need fresh prioritization before roadmap work resumes.
