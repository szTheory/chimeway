    ```elixir
    [
      [:chimeway, :policy, :evaluate, :stop],
      [:chimeway, :dispatch, :sync, :stop],
      [:chimeway, :dispatch, :perform, :stop],
      [:chimeway, :attempts, :record, :stop]
    ]
    ```

    Filter perform events at compile time same as `Chimeway.Telemetry.attach_default_handlers/0` — include `[:dispatch, :perform, :stop]` only when `Code.ensure_loaded?(Oban)`.

    **`attach/0`** — idempotent `:telemetry.attach_many/4` with `@handler_id`; rescue `{:already_exists, @handler_id}` → `:ok`. Return `:ok`.

    **`handle_event/4`** — public for `:telemetry` callback; wrap body in `try/rescue` — log at `:debug` and never raise into telemetry dispatch.

    **Config lookup** — `Application.get_env(:chimeway, :threadline_reporter, [])`; require `repo:` and `actor:` (`%Threadline.Semantics.ActorRef{}`). On missing config, log `:debug` and return `:ok` (no crash).

    **Outcome mapping** (D-05) on `:stop` metadata `meta` (already redacted by Chimeway emitters):

    | Event suffix | Condition | Action atom | reason string source |
    |---|---|---|---|
    | `[:policy, :evaluate, :stop]` | `Map.has_key?(meta, :suppression_reason)` | `:notification_suppressed` | `meta.suppression_reason` |
    | `[:policy, :evaluate, :stop]` | `Map.has_key?(meta, :planning_reason)` and no suppression | `:notification_deferred` | `meta.planning_reason` |
    | `[:dispatch, :sync, :stop]` or `[:dispatch, :perform, :stop]` | `meta.outcome != :failed` (or absent outcome) | `:notification_dispatched` | `"dispatched"` |
    | `[:attempts, :record, :stop]` | `meta.outcome == :failed` | `:notification_failed` | `"failed"` |

    Precedence: on policy span, check `suppression_reason` before `planning_reason`.

    Skip `:notification_succeeded` — ECOS-08 four outcomes only.

    **OQ-1 resolution:** Fire `:notification_dispatched` on dispatch `:stop` when outcome is not `:failed`; do **not** add in-memory dedupe map in Phase 63 — document in moduledoc that sync vs perform should not double-fire for same delivery in default test config.

    **`record_action/2` call** — for each matched outcome:

    ```elixir
    Threadline.record_action(action_atom,
      repo: repo,
      actor: actor,
      correlation_id: meta[:correlation_id],
      category: "notifications",
      reason: reason_string,
      comment: build_comment(meta)
    )
    ```

    **`build_comment/1`** — deterministic key=value pairs from allowed meta keys only: `delivery_id`, `notification_key`, `channel`, `attempt_id`, `outcome`, `attempt_number`, `error_class`. Join with `; `. Cap total length at 512 chars (truncate with `...`). Never include payload, email, template, or provider response fields (D-06).

    Do **not** implement `Chimeway.Adapter` callbacks. Do **not** auto-attach at library boot — host calls `attach/0` explicitly (D-03).
