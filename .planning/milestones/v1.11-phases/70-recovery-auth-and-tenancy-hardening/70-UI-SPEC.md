## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Field hints, confirmation text spacing, status dot gaps |
| sm | 8px | Compact row gaps, inline recovery metadata, auth/tenant scope chips |
| md | 16px | Default card padding, list gaps, form gaps, alert padding |
| lg | 24px | Recovery panel padding, section heading separation, tenant-scope banner spacing |
| xl | 32px | Main content padding on desktop, two-column recovery grid gap |
| 2xl | 48px | Major vertical section separation only |
| 3xl | 64px | Page-level spacing only; avoid inside recovery cards and confirmation forms |

Exceptions: retain Phase 69 exceptions. Recovery submit, candidate buttons, navigation targets, and confirmation controls must be at least 44px high on mobile and 40px high on desktop. Status pills and read-only scope labels may be 26px minimum height. 1px borders and 3px focus outlines are allowed.

Implementation contract: continue using `--cw-space-*` tokens under `.chimeway-admin`. Do not introduce raw spacing values in new Phase 70 selectors except 1px borders and the existing 3px focus outline. Recovery-specific additions should extend `.cw-alert`, `.cw-confirm-form`, `.cw-summary-list`, `.cw-row-link`, and optional `.cw-scope-*` classes rather than adding page-local layout one-offs.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | light `#fffdf8`; dark `#07131a` | Root page background and broad reading surface |
| Secondary (30%) | light `#ffffff` / `#f7f4ea`; dark `#10232c` / `#0b1b23` | Cards, sidebar, nav, rows, inputs, summary lists, tenant-scope banner |
| Accent (10%) | light `#0e7c86`; dark/system-dark `#9adbcf` | Active Recovery nav item, selected candidate row, focus-adjacent highlights, safe informational scope labels |
| Destructive | light `#b83232`; dark `#ffb3b3` button token | Recovery submit action, destructive confirmation state, authorization denial/error state only |

Accent reserved for: active navigation, selected candidate row, primary non-destructive CTA if added, focused/selected row emphasis, `.cw-eyebrow`, and informational tenant-scope labels. Accent must not be used for destructive recovery submit, generic body links, or decorative gradients that compete with candidate facts.

Semantic color contract:

- Keep `.chimeway-admin[data-cw-theme="light|dark|system"]` from Phase 69.
- Recovery success uses existing success status tokens; stale/noop uses warning status tokens; authorization denial and failed recovery use danger tokens; tenant-scope informational context uses info/neutral tokens.
- Destructive submit must use `.cw-button--danger` and preserve AA contrast in light, dark, and system-dark themes.
- Alerts must not rely on color alone: include explicit status text such as `Recovery skipped`, `Recovery failed`, or `Recovery started`.

Source: Phase 69 UI-SPEC color contract, REQUIREMENTS SAFE-02/SAFE-03, and current `RecoveryLive` flash/noop behavior.

## Interaction Contract

| Surface | Contract |
|---------|----------|
| Recovery page structure | Preserve the existing two-panel flow: `Eligible work` list on the left/top and `Confirm recovery` review form on the right/below. Mobile stacks panels in that order. |
| Visual priority | Primary visual anchor is the selected candidate review panel once a row is chosen; before selection, the eligible recovery list is the first-priority scanning surface. |
| Candidate selection | Candidate rows remain buttons, not links. Selecting a row must set a visible selected state, populate the review panel, and clear stale prior result messaging. |
| Tenant scope | When a host-provided tenant scope is active, show one compact read-only scope label near the page heading or recovery list. Copy: `Tenant scope: {tenant_id}`. If no tenant scope is provided, omit the label; do not invent tenant membership UI. |
| Confirmation | Recovery requires deliberate confirmation beyond row selection. Use the required `Recovery reason` field plus a required confirmation marker such as a checkbox or exact text input. The submit button remains disabled until the confirmation marker is satisfied. |
| Submit action | Submit label is `Recover this {event|delivery}` and uses the danger button variant. Submission re-authorizes at event time with actor, action, tenant scope, resource id, recovery type, and selected candidate facts before calling core recovery APIs. |
| Stale/noop outcome | Stale or ineligible candidates are normal outcomes. Clear the selected candidate, refresh the list under the current tenant scope, and show a warning-tone status message instead of a fatal error. |
| Authorization denial | Unauthorized submit redirects/fails closed via `LiveAuth.ensure_authorized/3`. Do not show raw policy context, session, params, or candidate internals in the UI. |
| Durable evidence | The review panel may display safe evidence fields only: type, notification key, reason, correlation id, tenant id when present, resource id, actor reference when safe, and confirmation marker. |
| Focus and keyboard | Candidate rows, reason input, confirmation marker, and submit button must be reachable in DOM order. Focus visible uses the Phase 69 3px outline and 3px offset. No transform on focus. |
| Motion | Use Phase 69 motion only: 120ms color/border/background transitions and 80ms pressed feedback. Reduced-motion media query must reduce transitions to near-zero. |

Out of scope: Phase 70 must not add raw payload/render/provider-body displays, broad DTO privacy leak tests, explanation-copy taxonomy changes, docs gate composition, or browser-smoke gate work.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | Recover this {event\|delivery} |
| Empty state heading | No recoverable work |
| Empty state body | Nothing currently meets the recovery safety threshold. |
| Selection empty state heading | Choose a candidate |
| Selection empty state body | Select one eligible row to review the exact recovery action. |
| Stale/noop state | Recovery skipped: the row is no longer eligible. Refresh Recovery to review current candidates. |
| Error state | Recovery failed. The row may no longer be eligible; refresh Recovery and try again with a current candidate. |
| Authorization denial | Do not render custom denial copy in the recovery page; fail closed through the configured unauthorized redirect. |
| Destructive confirmation | Recover this {event\|delivery}: require `Recovery reason` plus a deliberate confirmation marker before submission. |

Copy source: existing `RecoveryLive`, Phase 69 UI-SPEC, REQUIREMENTS SAFE-02/SAFE-03, and Phase 70 CONTEXT D-10/D-11. New copy is limited to stale/noop next-step clarity, tenant-scope labeling, and deliberate confirmation. Do not add Phase 71 redaction/explainability wording.

## Recovery Safety UI Details

| State | Required UI Behavior | Evidence Boundary |
|-------|----------------------|-------------------|
| Candidate list loaded | Show up to the current limit of eligible rows scoped by admin context. Each row displays type, notification key, reason, and status badge. | Candidate DTO fields only. |
| Candidate selected | Review panel displays type, notification key, reason, correlation id, resource id, and tenant id when present. | No raw session, params, payloads, provider bodies, secrets, tokens, auth codes, or full PII. |
| Confirmation ready | Submit becomes enabled only after required reason and confirmation marker are present. | Confirmation marker may be persisted as a safe boolean/string, not raw form data. |
| Recovery started | Show success-tone alert with existing result copy, then refresh candidates under the same tenant scope. | Durable metadata includes safe source/reason/actor/confirmation facts only. |
| Recovery skipped/noop | Show warning-tone alert with stale/noop copy, clear selection, refresh candidates. | Treat as explainable normal outcome, not exception. |
| Recovery failed | Show danger-tone alert with safe problem/next-step copy. | Do not inspect or display raw error internals if they may include sensitive values. |
