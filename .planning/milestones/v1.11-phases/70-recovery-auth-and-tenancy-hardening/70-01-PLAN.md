<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| Host Phoenix app to `chimeway_admin` LiveViews | Host supplies actor/session/query context; ChimewayAdmin consumes it but does not own auth policy. |
| `chimeway_admin` LiveViews to core Chimeway reads | UI passes tenant read opts into core read-model functions. |
| Core read queries to database | Tenant filters must be applied before DTO rows are returned. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|---|---|---|---|---|
| T-70-01-01 | Spoofing / Tampering | Tenant values from query params or session | mitigate | `ChimewayAdmin.Context.from/3` normalizes tenant scope but treats it as host context only; `authorize/3` receives tenant scope so host policy can validate it per D-02 and D-06. |
| T-70-01-02 | Elevation of Privilege | Mount or event authorization context lacks resource facts | mitigate | `LiveAuth` uses `Context.authorize_context/3` with actor, action, params, session, tenant scope, and supplied resource facts while keeping D-01 arity stable. |
| T-70-01-03 | Information Disclosure | Admin LiveViews call `Chimeway.admin_*` without tenant opts | mitigate | Dashboard, health, feed, definitions, and recovery use `Context.read_opts/2`; `test/chimeway/admin_test.exs` proves cross-tenant exclusion. |
| T-70-01-04 | Information Disclosure | Event recovery candidates without durable tenant proof leak under scoped reads | mitigate | `Chimeway.Admin.recovery_candidates/1` omits no-delivery event candidates when `tenant_id` is present unless durable tenant ownership can be proven. |
| T-70-01-SC | Tampering | Package manager installs | accept | No dependency install is planned; RESEARCH records no new packages. |
</threat_model>
