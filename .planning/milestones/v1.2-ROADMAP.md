# Milestone v1.2: Delivery Orchestration

**Status:** ✅ SHIPPED 2026-04-29
**Phases:** 17-23
**Total Plans:** 29

## Overview

Chimeway v1.2 turned the durable core into a product-grade orchestration layer: delivery windows, deferred resume, digest accumulation and emission, durable rendering contracts, recovery/reconciliation flows, and outcome analytics all now run through explainable canonical records.

## Phases

### Phase 17: Delivery Windows & Deferral Semantics

**Goal**: Define the durable planning model for immediate sends, quiet-hours deferral, and recipient-timezone-aware delivery windows.
**Depends on**: Phase 16
**Plans**: 3 plans

Plans:

- [x] 17-01: Add orchestration-state persistence and quiet-hours policy storage
- [x] 17-02: Persist explicit planning outcomes on canonical delivery rows

## Milestone Summary

**Key Decisions**

- Prioritize orchestration behavior before channel breadth so Chimeway solves timing, batching, and recovery before expanding providers.
- Keep deferred, digest-held, resumed, recovered, and emitted flows anchored to one canonical delivery row wherever possible.
- Persist rendering and orchestration declarations as durable data so replay and preview do not depend on notifier module re-entry.
- Keep automatic digest scheduling explicitly scoped to Oban-backed hosts and preserve `emit_bucket/2` as the non-Oban host seam.

**Issues Resolved**

- Quiet-hours deferral, deferred resume, and digest-held planning now persist explainable lifecycle facts instead of relying on transient runtime state.
- Digest accumulation, scheduling, and emitted dispatch now run end to end through production code rather than manual operator intervention.
- Rendering identity and payload shaping are durable, validated, previewable, and decoupled from notifier module names.
- Recovery and grouped outcome analytics close the remaining operational trust gaps for persisted-but-not-fully-dispatched flows.

**Issues Deferred**

- Workflow journeys and escalations beyond single-notification orchestration remain deferred for a later milestone.
- Broad provider/channel expansion remains deferred until orchestration behavior and workflow priorities are defined.

**Technical Debt**

- Nyquist validation discovery artifacts remain partial across milestone phases even though no delivery, digest, or verification blocker remains open.
- No next milestone is defined yet; fresh requirements and roadmap work are needed before active development continues.
