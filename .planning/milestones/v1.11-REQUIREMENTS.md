# Requirements: Chimeway v1.11 Operator Console Polish & Hardening

**Defined:** 2026-06-04
**Core Value:** Every notification decision is explainable, so teams can reliably answer why a notification sent, failed, was deferred, or was suppressed.

## v1.11 Requirements

### Operator Console IA

- [x] **ADMIN-01**: Operator can land on `/admin/chimeway` and immediately choose the right path for health, trace investigation, recipient feed debugging, definitions, or recovery.
- [x] **ADMIN-02**: Operator can move through command center, traces, detail, feed, definitions, health, and recovery screens with consistent navigation, labels, and page hierarchy.
- [x] **ADMIN-03**: Operator-facing docs and demo copy accurately describe the current admin pages and no longer overclaim or mark shipped pages as out of scope.

### Design System and Accessibility

- [x] **DES-01**: Admin UI uses scoped Chimeway design tokens for color, spacing, typography, status, radius, shadow, focus, z-index, and motion.
- [x] **DES-02**: Admin UI supports light, dark, and system theme behavior with accessible contrast and no broken hover, focus, or active states.
- [x] **DES-03**: Admin UI remains usable on mobile and desktop, with no overlapping text or unstable layout shifts in core operator flows.
- [x] **DES-04**: Admin UI uses purposeful, reduced-motion-safe microinteractions for state changes without slowing keyboard-heavy workflows.

### Safety, Tenancy, and Recovery

- [x] **SAFE-01**: Recovery actions re-authorize the actor for the specific action and resource context at event time.
- [x] **SAFE-02**: Recovery handles stale or no-longer-eligible candidates without duplicate or misleading actions.
- [x] **SAFE-03**: Recovery UI requires explicit confirmation and records durable evidence through core recovery APIs.
- [x] **SAFE-04**: Admin read models and LiveViews support tenant-scoped operation through host-provided auth/session/query context.

### Redaction and Explainability

- [x] **PRIV-01**: Rendered admin HTML does not expose raw payloads, render data, provider bodies, tokens, secrets, auth codes, or full recipient PII.
- [x] **PRIV-02**: Admin DTOs expose only stable, explainable fields needed for operator decisions.
- [x] **EXPL-01**: Trace/detail/status language distinguishes sent, provider accepted, delivered, suppressed, retryable failure, and terminal failure.
- [x] **EXPL-02**: Definitions screen clearly communicates DB-inferred definition/version history and does not overclaim code-registry skew detection unless implemented.

### Documentation and Verification

- [x] **DOCS-12**: Maintainer can follow a canonical admin integration guide covering router mount, static assets, auth behavior, route prefixing, recovery permissions, redaction, and production fail-closed expectations.
- [x] **GATE-08**: Maintainer can run `mix verify.admin` locally and in CI to verify core admin read models, `chimeway_admin`, and demo-host mounted admin coverage.
- [x] **SMOKE-01**: Maintainer can run a browser smoke that proves the mounted admin console is nonblank, styled, navigable, and usable across the core pages.

## Future Requirements

### Deferred Operator Capabilities

- **ADMIN-F01**: Operator can dry-run replay a notification decision before recovery.
- **ADMIN-F02**: Operator can inspect richer Oban queue/backlog metrics when Oban is configured.
- **ADMIN-F03**: Operator can inspect provider-specific response summaries through opt-in redaction hooks.
- **INBX-03**: End user sees real-time PubSub bell badge updates in `chimeway_inbox`.
- **ADPT-01**: Maintainer can run greenfield `phx.new` plus Hex dependency install smoke in CI.

## Out of Scope

| Feature | Reason |
|---------|--------|
| Generic CRUD admin over Chimeway tables | Chimeway's job is process explainability, not table editing. |
| Template editing or provider configuration UI | Host apps own notifier code and provider configuration. |
| Visual workflow/DAG editor | Large product surface; not needed for operator trace and recovery hardening. |
| Arbitrary bulk resend/delete | High user-impact risk; recovery must stay narrow and auditable. |
| SaaS or external control-plane dashboard | Chimeway is local-first embedded infrastructure. |
| Advanced cohort analytics | Useful later, but lower leverage than support/debug/recovery clarity. |
