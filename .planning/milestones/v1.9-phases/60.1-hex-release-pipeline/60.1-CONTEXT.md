**In scope:** ci-gate + Release Please JSON, hardened `release.yml`, automerge + recovery workflows, MAINTAINING runbook update, `release_gate_contract_test.exs` extensions.

**Out of scope:** Inbox phases 61–62; post-publish daily cron; mandatory `RELEASE_PLEASE_TOKEN` before bootstrap; repo rename hygiene; `install_golden_contract` as universal ci-gate lane.

<decisions>
## Implementation Decisions

### Template and version SSOT
- **D-60.1-01:** Canonical template = `~/projects/lattice_stripe/.github/workflows/{release,release-pr-automerge,publish-hex}.yml` + `release-please-config.json` + `.release-please-manifest.json`.
- **D-60.1-02:** First automated semver after Hex 1.0.0 = **1.1.0**; manifest seeds at `"." : "1.0.0"` matching `mix.exs`; Release Please drives subsequent bumps from conventional commits — no manual `@version` edit on `main`.
- **D-60.1-05:** SHA-pin all actions in release workflows (match existing `ci.yml` convention).

### ci-gate composition (8 required lanes)
- **D-60.1-03:** `ci-gate` aggregates eight jobs: `lint`, `test`, `verify_gates`, `verify_docs`, `verify_example`, `verify_journeys`, `verify_mailglass`, `verify_accrue`. Pattern: lattice_stripe `ci-gate` with `if: always()` + fail if any required lane ≠ success.
- **D-60.1-06:** Retire standalone `.github/workflows/docs.yml`; add `verify_docs` job running `mix ci.docs` in `ci.yml` and include in `ci-gate`.
- **D-60.1-07:** Add dedicated `verify_gates` job running `mix ci.verify_gates` in `ci.yml` and include in `ci-gate`; also run in `release.yml` publish pre-publish (belt + suspenders). Optional follow-up: exclude doc-contract test files from `ci.test` to avoid double-running on OTP matrix.
- **D-60.1-08:** `install_golden_contract` stays path-gated and **outside** `ci-gate` — do not change MAINTAINING gating behavior.

### Publish gating
- **D-60.1-04:** Publish blocked unless `ci-gate` green on release SHA (lattice `gate-ci-green` pattern with tag-dispatch fallback).
- **D-60.1-10:** `publish-hex.yml` recovery gates on `ci-gate` only — copy inline `github-script` poll from `release.yml`; reject lattice recovery's per-job prefix checks and lint-failure allowance.

### Release PR bootstrap and automerge
- **D-60.1-09:** Wave 1: add `workflow_dispatch` to `ci.yml` + `bootstrap-release-pr-ci` in `release.yml`; **manual merge** of bootstrap 1.1.0 release PR. Wave 2: port `release-pr-automerge.yml` after ci-gate proven on `release-please--*` branches.
- **D-60.1-11:** `RELEASE_PLEASE_TOKEN || GITHUB_TOKEN` in release-please step; document PAT as optional upgrade in MAINTAINING if native release-PR CI remains flaky.

### Publish pre-publish replay (defense in depth)
- **D-60.1-12:** `publish-hex` pre-publish runs: `mix compile --warnings-as-errors`, grep `@version`, `mix ci.verify_gates`, `mix ci.docs`, `mix hex.build`, idempotency skip, Hex API poll — mirror lattice_stripe hardened publish path adapted for chimeway verify lanes.

### Claude's Discretion
- Exact poll timeouts for recovery vs happy-path (recovery may use shorter budget; maintainer assumes CI already ran).
- Whether to add optional `push: branches: ['release-please--**']` on `ci.yml` alongside dispatch bootstrap.
- Extract `.github/actions/wait-for-ci-gate` composite only if a third caller appears post-60.1.

</decisions>
