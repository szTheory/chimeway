## Milestone Summary

**Key Decisions:**

- `cancel_signals` validated at notifier declaration time, not runtime (D-06)
- `pending_signals` column is sole durable source — not mirrored into status_context
- Inbox signals on first read/seen transition only; lifecycle `:ok` independent of Signal.track (D-07)
- `signal_received` transition context is event_name only — no payload in traces (READ-03)
- READ-driven demo replaces staged webhook seed choreography

**Issues Resolved:**

- READ-01 engine gap: `wait_until` now auto-populates `pending_signals`
- READ-02/03: inbox lifecycle emits durable signals with explainable early resume
- Staged `PendingWebhookAdapter` escalation masked real READ path — removed
- Demo README webhook contradiction and `demo.up --check` moduledoc drift
- Nyquist validation metadata for Phases 48–51; ConnCase deprecation in journey tests

**Issues Deferred:**

- Inbox-read `signal_received` may not project onto delivery timeline UI (INT-02)
- `mark_seen` progression E2E not covered — emission only (INT-03)
- SEED-003 ecosystem plugins → v1.8
- INBX bell UI → v1.9

**Technical Debt Incurred:**

- Operator UI projection of inbox-read signals onto delivery timeline (optional v1.8)
- `mark_seen` cancel-signal routing lacks progression E2E proof
