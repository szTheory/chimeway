# Closure Plan (decided 2026-06-02, research-backed)

Four parallel research streams (in-house precedent map, prompts/vision corpus, idiomatic
Elixir survey, current-state code map) converge on one decisive answer. **Do not vendor the
Sigra integration into chimeway.** Follow the proven **Accrue precedent** exactly.

## The architectural verdict

Chimeway has two integration directions, each with its own correct home for glue code:

- **OUT (chimeway → partner):** chimeway owns the adapter/reporter in its tracked `lib/`.
  Precedents: `Chimeway.Adapters.Mailglass`, `Chimeway.Telemetry.ThreadlineReporter`. These
  work in CI because the code is chimeway's own and only needs the partner module to *exist*.
- **IN (partner → chimeway):** the **partner repo owns** `Partner.Integrations.Chimeway`,
  pinned in chimeway CI via a sibling `actions/checkout` at a SHA that contains the integration
  commit. The single working precedent is **Accrue** (`Accrue.Integrations.Chimeway`, CI ref
  `236fa2f1` which *contains* accrue commit `b380e08a`).

`Sigra.Integrations.Chimeway` is the IN direction and is structurally identical to Accrue.
It is **already committed to `szTheory/sigra`** (introduced `c2a34b76`, completed `c7f06d92`,
on `origin/main` HEAD `62ceb46a`). The only defect is that CI pins `b186f03c`, which predates
those commits — so the sibling checkout is empty and the gate passes vacuously. This is a
**pin-lag, not a missing artifact.** Vendoring would invent a new pattern with no precedent,
contradict the partner-owns-its-domain seam philosophy (`prompts/chimeway-host-app-integration-seam.md:3-17`),
and violate the corpus's documented "reference-canonical over vendor-a-copy" preference
(`prompts/prior-art/README.md:7-8`). The BEAM single-module-load rule also makes
`Sigra.Integrations.Chimeway` correct only if **Sigra** ships it (Elixir naming convention;
mirrors `Dataloader.Ecto`). Idiomatic Elixir agrees: the reactor owns the guarded glue,
namespaced under itself.

## Recommendations (one cohesive closure phase — all serve the north-star: explainability + honest gates)

**R1 — Repin the Sigra CI SHA (closes BLOCKER-1, BLOCKER-2; unblocks ECOS-09, DEMO-10, GATE-07).**
`ci.yml:407` `ref: b186f03c…` → `ref: 62ceb46a38c4e617f6c06d874ecb12e1ab19d97c` (origin/main HEAD;
contains `c2a34b76..c7f06d92`). Minimal alternative: pin the exact integration-complete commit
`c7f06d92`. This is the entire root-cause fix and exactly mirrors how Accrue is wired. No
vendoring, no new pattern.

**R2 — Make the vacuous pass impossible, symmetrically across sigra + accrue + threadline
(closes WARNING-2; the real systemic lesson).** The prompts corpus already named this exact
footgun: *"Hidden heavy tests excluded from default `mix test` without contributor-visible
policy (threadline / sigra lesson)"* (`chimeway-engineering-dna-from-prior-libs.md:96`). Fix the
*class*, not the instance:
  - (a) `test/test_helper.exs` (sigra + accrue blocks): the "integration file missing on disk"
    branch currently **silently skips** — change it to **raise loud** (it already raises on a
    failed *compile*; extend that to a missing *file*).
  - (b) Harden the harness tests, which are guarded only on the partner module and so always
    run: `sigra_auth_harness_test.exs` must hard-assert `Code.ensure_loaded?(Sigra.Integrations.Chimeway)`
    and `function_exported?(Chimeway, :trigger, 3)` (today it only checks `Sigra.Auth`). Mirror
    for accrue/threadline harnesses. This guard sits *outside* the lifecycle double-guard, so an
    absent integration turns RED instead of silently green.
  - (c) Add a floor assertion to `release_gate_contract_test.exs`: each verify lane must run
    ≥ its expected integration-test count (the doc-contract discipline applied to test execution).

**R3 — Fix the Sigra golden-path guide (closes WARNING-1; DOCS-10).**
`guides/introduction/sigra-auth-integration.md:66` shows the invalid
`Chimeway.trigger("sigra.auth.magic_link", recipient, params: …)`. `trigger/3` takes a **notifier
module** first arg (`trigger.ex:46,60 validate_module!`) and has no `params:` option. Correct it
to the real call shape (notifier module + params map + `idempotency_key`/`tenant_id`/`correlation_id`
opts), matching the blueprint and `seeds.ex:280`. Also fix WR-2 (the `Mod.fun/0` arity notation
inside ```elixir fences in both guides → move to inline code or a non-elixir fence).

**R4 — Strengthen the doc-contract so it would have CAUGHT R3 (DOCS-11).**
Per `chimeway-testing-and-e2e-strategy.md:16-18` (snippets must compile / match public API), the
sigra describe block in `doc_contract_test.exs` is substring-only. Add forbidden patterns
`Chimeway.trigger("` (string-first-arg) and `params:` in the guide, and assert the trigger
example references a `*Notifier` module. Tighten WR-3 (prefix-only `seed_sigra` pin → full name).

**R5 — Verify Phase 64 and reconcile tracking (closes the unverified-phase blocker; ECOS-09).**
After R1–R4, run `mix verify.sigra` under clean-CI conditions, then produce `64-VERIFICATION.md`
proving ECOS-09 E2E. Commit the untracked `64-02-SUMMARY.md`; flip ROADMAP (64-02 `[x]`, phase
Complete) and REQUIREMENTS/Traceability (ECOS-09 `[x]`, Complete).

**R6 — Nyquist closeout + minor hygiene.** All four `*-VALIDATION.md` are `status: draft`,
`nyquist_compliant: false` — the corpus forbids silently-deferred Nyquist debt: *"deferred

**Vehicle:** one closure phase (~2 waves). R1 is one line; R2/R4 harden the gates; R3 fixes docs;
