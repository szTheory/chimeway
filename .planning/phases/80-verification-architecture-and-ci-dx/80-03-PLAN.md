## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Extracted script → CI step | A script that silently diverges from the inline logic it replaced could weaken a gate (e.g. narrowed detect regex, dropped Sigra env). |
| Local run → CI run | The same script must behave identically locally and in CI (env-var contract parity). |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-80-07 | Tampering | installer detect regex narrowed during extraction | high | mitigate | Copy the regex verbatim; contract test asserts a verbatim regex substring in the detect script, so a paraphrase fails `mix ci.verify_gates`. |
| T-80-08 | Tampering | Sigra proof strictness lost when moving strings out of ci.yml | high | mitigate | Contract test re-asserts every load-bearing Sigra string against the script content and that verify_sigra calls the script (D-14 "at least as strict"). |
| T-80-09 | Tampering | aggregate-gate script mis-handling `skipped`/`cancelled`/`failure` | medium | mitigate | Script fails on any non-`success` (mirrors the original loop); tested locally with a non-`success` env in the task verify. |
| T-80-SC | Tampering | npm/pip/cargo installs | low | accept | No package installs; scripts are repo-local bash invoked with pinned-action-provided toolchains. |
</threat_model>
