<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Cache store → CI job | A restored cache is trusted build state; a stale/poisoned cache could mask a real dependency change. |
| Cross-lane cache sharing | Different verify lanes resolve demo-host optional deps differently; a shared key crosses a resolution boundary. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-80-05 | Tampering | stale/poisoned cache masking a bad or drifted dependency | high | mitigate | All `_build`/`deps` caches key on `mix.lock`/`package-lock.json` only (D-12); contract test asserts every `hashFiles()` references a lockfile, so a source-keyed cache fails the gate. |
| T-80-06 | Tampering | shared demo-host cache serving a foreign optional-dep resolution | medium | mitigate | Per-lane cache key includes the lane slug (D-11); contract test asserts distinct per-lane keys, so a shared key fails the gate. |
| T-80-SC | Tampering | npm/pip/cargo installs | low | accept | No new package installs; `actions/cache`/`setup-node` reuse existing pinned SHAs. Cache scope is deps/browsers keyed on lockfiles. |
</threat_model>
