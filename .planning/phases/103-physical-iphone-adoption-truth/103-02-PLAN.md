## Trust Boundaries

| Boundary | Description |
|---|---|
| Operator environment -> physical runner | Signing/device/host inputs are untrusted prerequisites and must never be echoed or retained. |
| CI -> support truth | Credential-free contract success proves release readiness only, not physical behavior. |
| Documentation -> adopter decisions | Inaccurate or duplicated wording can cause unsafe operational conclusions. |
| Source pin -> CI checkout | A stale/floating/mutable CrossWake revision could silently validate different semantics. |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-103-07 | Information Disclosure | physical runner preflight/output | high | mitigate | Stable ordered rule/outcome output excludes checked values, credentials, device data, endpoints, paths, and authority bytes. |
| T-103-08 | Spoofing | Threshold-A support state | high | mitigate | Release/doc contracts require release_ready_physical_pending and reject package/CI/provider evidence as physical proof. |
| T-103-09 | Tampering | CI CrossWake checkout | high | mitigate | Pin Plan 103-01's full SHA, assert canonical remote/HEAD/clean state, and keep both aggregate-gate links contract-tested. |
