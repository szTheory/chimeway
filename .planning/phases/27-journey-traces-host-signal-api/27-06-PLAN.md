<objective>
Fix three independent defects in the signal-routing and inspection surface that all live in `lib/chimeway/workflows.ex` and the Oban configuration:

1. **CR-02 (BLOCKER):** `find_runs_waiting_for_signal/2` issues `FOR UPDATE` row locks OUTSIDE the `Repo.transaction` that performs the writes. PostgreSQL releases row locks at transaction commit; with no enclosing transaction at lock time, locks evaporate before the write transaction begins. Two concurrent `SignalRouterWorker` jobs can both succeed and produce duplicate `signal_received` transition rows.

2. **CR-03 (BLOCKER):** `SignalRouterWorker` uses `queue: :signals` which is not declared in any Oban configuration file. Jobs sit in `:available` forever in any non-test deployment.

3. **WR-06 (WARNING):** `list_traces/3` documents a `:limit` opt but matches `_opts \\ []` and never reads it. Long-running workflows can return unbounded transition lists.

Purpose: Three correctness defects that share the same surface area (`workflows.ex` + the Oban worker). All three are independent of the tenant-threading work in plan 27-05, but they overlap on `lib/chimeway/workflows.ex` so they must serialize relative to 27-05 (this plan runs first; 27-05 runs after).
Output: `route_signal/1` with the lock inside the transaction; an Oban queue declaration in every relevant config file matching the worker's queue atom; and `list_traces/3` honoring `:limit`.

**Closes gaps:** CR-02 (BLOCKER), CR-03 (BLOCKER), WR-06 (WARNING).
</objective>

    when is_binary(tenant_id) and is_binary(event_name) do
  matched_runs = find_runs_waiting_for_signal(tenant_id, event_name)  # OUTSIDE transaction!

  multi =
    Enum.reduce(matched_runs, Multi.new(), fn run, acc ->
      now = DateTime.utc_now()

  end

defp find_runs_waiting_for_signal(tenant_id, event_name) do
  Repo.all(
    from(wr in WorkflowRun,
      where: wr.tenant_id == ^tenant_id and wr.state == :waiting and ^event_name in wr.pending_signals,
      lock: "FOR UPDATE"   # Lock released the moment Repo.all returns — no enclosing transaction

end

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Concurrent SignalRouterWorker jobs -> chimeway_workflow_runs | Two concurrent jobs for the same (tenant_id, event_name) must serialize on FOR UPDATE row locks held through transaction commit |
| Oban queue declaration -> SignalRouterWorker module | Worker queue atom and config queue atom must agree, or jobs accumulate in :available state and the entire signal-routing pipeline is silently dead |
| Operator inspection -> chimeway_workflow_transitions (large result set) | :limit must be honored to bound query result size for long-running workflows |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-27-10 | Tampering | route_signal/1 concurrency race | mitigate | Move FOR UPDATE lock acquisition inside Repo.transaction so locks survive until commit; concurrent worker for the same signal blocks on the row lock and re-reads after commit, finding the run already :active and pending_signals == [] — its `where ^event_name in pending_signals` no longer matches. |
| T-27-11 | Denial of Service | Undeclared Oban queue silently swallowing all signal jobs in production | mitigate | Declare the queue in every Oban config; align worker module attribute and config keyword list on `:chimeway_signals`. |
| T-27-12 | Denial of Service | list_traces/3 unbounded for long-running workflows | mitigate | Honor the :limit opt that has been documented but ignored; default remains unbounded for backward compatibility, but callers can now bound the response. |
</threat_model>
