## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| canonical delivery convergence -> workflow progression | Delivery outcomes cross into workflow state changes and next-step emission |
| workflow run current state -> next-step planning | One aggregate row controls later delivery creation and must not be advanced twice |

| T-25-04 | T | `lib/chimeway/workflows/progression.ex` | mitigate | Lock workflow runs and active-step deliveries inside one transaction, derive outcomes from persisted rows only, and persist exact anchor/evidence facts before advancing. |
| T-25-05 | R | `lib/chimeway/workflows.ex` / `workflow_transitions` | mitigate | Append explicit reasons `waiting_for_step_progression` and `progressed_on_delivery_outcome` with durable context keys so operators can audit why a run waited, advanced, or no-oped. |
| T-25-06 | D | `lib/chimeway/deliveries.ex` progression hook | mitigate | Make progression re-entry noop-safe when rows are not branchable, already advanced, or lack workflow linkage; this prevents retry storms from emitting duplicate next-step deliveries. |
