<interfaces>
`Chimeway.Adapters.APNS.deliver/2` owns four pre-provider stages in order: stored `RequestIntent` validation, expiry check, exact `BindingLookup.resolve/1`, and closed `Payload.build/2`. None proves request emission. Only the following `Transport.push/2` call crosses the provider-handoff boundary, so only that call's timeout/exit/connection-loss/missing-response guard may return possible handoff per D-13.

`BindingLookup.resolve/1` normally returns `{:error, :binding_not_found}` for a malformed or mismatched result. A host callback raise/catch is a distinct transient local lookup failure. Normalize it to `{:pre_handoff_retryable, %{provider_code: "binding_lookup_failed"}}`; do not include the exception term. Invalid stored intent or a payload construction exception remains terminal with the existing bounded invalid-request vocabulary.

`APNS.deliver/2` needs a testable pre-provider payload boundary. Resolve an internal `:apns_payload_builder` application module with `Chimeway.APNS.Payload` as the default and invoke its existing `build/2` contract. Tests temporarily install a raising module and restore the prior setting. This is an internal injection seam only: do not add a public API, dependency, durable field, or alternate production payload format.

`DeliveryTargets.record_target_outcome/5` already maps `:pre_handoff_retryable` to a pending target and a failed attempt. The integration regression must enter through the real APNS adapter, reload both records, and prove the attempt facts contain the safe lookup-failure code while excluding `possible_provider_handoff`.

The packaged enabled consumer compiles Chimeway before running its own `mix compile --warnings-as-errors`. After `mix deps.get --check-locked`, the script must force a warning-strict compilation from `deps/chimeway` itself (for example through `mix cmd --cd deps/chimeway mix compile --force --warnings-as-errors`) before compiling/testing the consumer.

<gap_closure_root_cause>
`APNS.deliver/2` currently rescues the entire intent/expiry/lookup/payload/transport pipeline and therefore converts a local host lookup or payload-construction exception into possible provider handoff even though `Transport.push/2` was never invoked. Separately, `PigeonAdapter` contains an always-compiled dynamic callback implementation followed by a second compile-time-guarded implementation with the same callback heads; the second block is unreachable and calls a remote JSON helper that dependency compilation warns is undefined in this compilation context. The package script compiles Chimeway during dependency fetching before its later warning-strict consumer compile, so those warnings do not fail the gate.
</gap_closure_root_cause>
