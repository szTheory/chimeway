<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Host app CSS -> chimeway_admin CSS | Host applications mount ChimewayAdmin inside their Phoenix app; admin styles must remain scoped and resilient to host styles. |
| chimeway_admin CSS -> host app DOM | The packaged stylesheet must not leak global selectors or framework resets into host application pages. |
| Static asset -> operator browser | Operators rely on the packaged CSS for readable contrast, focus visibility, and reduced-motion preferences. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-69-01 | Tampering | `chimeway_admin/priv/static/chimeway_admin.css` scoping | mitigate | Keep selectors under `.chimeway-admin` or `:where(.chimeway-admin...)`; design-system tests forbid framework/global-style markers. |
| T-69-02 | Information Disclosure | admin UI polish scope | mitigate | This plan changes CSS and CSS tests only; do not modify DTOs, `ChimewayAdmin.Redaction`, LiveView data assigns, or rendered payload fields. |
| T-69-03 | Denial of Service | contrast and focus states | mitigate | Token tests sample foreground/background, muted, action, accent, and focus color pairs against WCAG 2.2 AA thresholds per D-05. |
| T-69-04 | Elevation of Privilege | theme/motion implementation | mitigate | Do not add JavaScript theme persistence, client storage, LiveView JS transitions, or auth/session changes; keep theme behavior CSS-first with `data-cw-theme` and media queries. |
