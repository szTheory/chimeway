<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| notifier module -> Chimeway persistence | Host-supplied notifier declarations become durable render facts |
| trigger planning -> delivery row | Render identity crosses from notification-level input capture to per-channel execution storage |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-21-01 | T | `lib/chimeway/notifier.ex` | mitigate | Normalize notifier rendering declarations into validated string channel keys plus explicit `render_key`/`render_version`; reject blank keys and invalid versions. |
| T-21-02 | T | `lib/chimeway/trigger.ex` | mitigate | Persist `render_assigns` once at trigger time per D-09 and keep `metadata` derived-only so late mutable host reads cannot rewrite content inputs. |
| T-21-03 | E | `lib/chimeway/delivery_planning.ex` | mitigate | Write render identity onto the canonical delivery row before policy/dispatch handoff so adapters and workers never infer identity from current module code. |
| T-21-04 | I | notification/delivery render fields | accept | Render identity fields are non-secret identifiers; no rendered body content is surfaced in this plan. |
</threat_model>
