<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| notification render inputs -> channel renderers | Durable input facts become per-channel render payloads |
| delivery row -> adapter execution | Pre-rendered content crosses from Chimeway planning into outbound transport code |
| delivery row -> operator traces | Stored render identity becomes user-facing explanation data |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-21-05 | I | `lib/chimeway/traces.ex` | mitigate | Project only `render_key` and `render_version`; explicitly exclude `render_data`, `html_body`, `text_body`, and transport blobs from explanation structs and timeline details. |
| T-21-06 | T | `lib/chimeway/delivery_planning.ex` | mitigate | Run `Chimeway.Rendering.render_delivery/4` during planning and persist the validated result so adapters and workers cannot late-render from mutable host state. |
| T-21-07 | E | `lib/chimeway/adapter.ex` / dispatch path | mitigate | Keep adapters transport-only and verify integration tests assert `render_data` already exists on the delivery row before `deliver/2` runs. |
| T-21-08 | R | channel contract tests | mitigate | Add explicit runtime validation failures for malformed in-app and email payloads so contract drift is detectable in CI instead of silently accepted. |
</threat_model>
