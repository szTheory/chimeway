<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| npm registry to repository | New browser test dependency enters the project through npm. |
| Browser test to demo host | Playwright drives a real browser against a Phoenix app with seeded operator data. |
| Rendered admin HTML to browser traces | Test output, failures, and screenshots may capture admin page content. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|---|---|---|---|---|
| T-72-02-01 | Tampering | `@playwright/test` install | mitigate | Use exact dev dependency `@playwright/test` version `1.60.0` from the research Package Legitimacy Audit; generate `package-lock.json` with npm, not by hand. |
| T-72-02-02 | Information Disclosure | Browser smoke page assertions and traces | mitigate | Use deterministic demo data only; do not seed payload/provider/render secrets in browser smoke; assert raw sensitive field names and full recipient PII do not appear in rendered HTML. |
| T-72-02-03 | Spoofing / Elevation of Privilege | Demo auth during smoke | accept with constraint | Demo host dev/test auth is permissive by design; smoke must not claim production auth succeeds by default and docs in Plan 72-01 cover fail-closed production setup. |
| T-72-02-04 | Denial of Service | Flaky browser startup | mitigate | `playwright.config.ts` webServer prepares DB, seeds demo data, starts port 4002, waits for readiness, and uses a bounded timeout. |
| T-72-02-SC | Tampering | npm/pip/cargo installs | mitigate | Research includes a valid Package Legitimacy Audit for `@playwright/test`; no [ASSUMED], [SUS], or [SLOP] packages are planned. |
</threat_model>
