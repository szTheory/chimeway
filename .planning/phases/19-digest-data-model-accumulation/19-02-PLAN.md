## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| canonical delivery rows -> accumulation transaction | The transaction must reject non-held or already-terminal deliveries instead of creating stale memberships |
| concurrent accumulation callers -> digest tables | Concurrent retries must not create duplicate memberships or inflate bucket counters |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-19-04 | T | `lib/chimeway/digests/accumulation.ex` | mitigate | Gate accumulation on `status == :pending` and `orchestration_state == :digest_held` after reloading the canonical delivery row inside the transaction. |
| T-19-05 | D | `lib/chimeway/digests/digest_membership.ex` | mitigate | Enforce one membership per `delivery_id` with a database unique index and use `on_conflict: :nothing` so retries cannot explode bucket size or lock the planner in repeated failures. |
| T-19-06 | I | digest bucket/member rows | mitigate | Snapshot only rule identity, grouping value, recipient scope, channel, and window facts; do not persist raw payload maps or provider metadata in membership rows. |
</threat_model>
