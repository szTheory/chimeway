| Boundary | Description |
|----------|-------------|
| host rule input -> `Chimeway.Digests` | Rule declarations are untrusted and must be validated before they become durable orchestration truth |
| persisted digest tables -> operator/debug surfaces | Digest storage must stay limited to explainable grouping/window facts and exclude sensitive payload content |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-19-01 | T | `lib/chimeway/digests/digest_rule.ex` | mitigate | Validate `group_by`, `window_kind`, and required window columns in changesets and back them with named unique indexes so invalid or conflicting rule identities cannot persist. |
| T-19-02 | R | `lib/chimeway/digests.ex` | mitigate | Persist stable `rule_key` + `rule_version` and snapshot `rule_key`/`rule_version` onto buckets so future traces can identify which rule created a bucket even after rule edits. |
| T-19-03 | I | digest table schemas | mitigate | Keep persisted columns limited to recipient scope, channel, grouping facts, and window metadata; do not add payload or provider-response fields to rules or buckets. |
</threat_model>
