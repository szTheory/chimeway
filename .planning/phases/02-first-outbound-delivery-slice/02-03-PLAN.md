  <files>test/support/chimeway/adapter/contract_test.ex</files>
  <read_first>lib/chimeway/adapter.ex, lib/chimeway/delivery.ex, test/chimeway/adapters/test_adapter_test.exs, .planning/phases/02-first-outbound-delivery-slice/02-RESEARCH.md</read_first>
  <action>Create `test/support/chimeway/adapter/contract_test.ex` defining `Chimeway.Adapter.ContractTest` using `defmacro __using__`. This pattern mirrors how Phoenix's `ConnCase` and `DataCase` inject shared setup — see how ExUnit's `use` macro works.

The macro must inject the following tests into any module that calls `use Chimeway.Adapter.ContractTest`:

**Contract test 1 — behaviour satisfaction**:
Assert the adapter module exports `deliver/2` via `:erlang.function_exported(adapter_module(), :deliver, 2)`. The test must call the adapter module provided by the using test's `adapter_module/0` function.

**Contract test 2 — success return shape**:
Call `adapter_module().deliver(sample_delivery(), [])` and assert:
- Result matches `{:ok, meta}` where meta is a map
- The meta map does not contain any of these keys (as atoms or strings): `password`, `token`, `secret`, `api_key`, `auth`

**Contract test 3 — redaction gate**:
Confirm the redaction assertion fails if a meta map containing `%{token: "abc"}` is passed to the check. This is a meta-test of the contract itself — write it as a test that calls the internal check function with a bad map and asserts it would fail.

**Contract test 4 (conditional) — error return shape**:
If the adapter's `simulate_error?/0` function returns `true`, call the adapter's `deliver_with_error/2` or configure it for failure and assert the return matches `{:error, reason_class, detail}` where `reason_class` is in `[:temporary, :permanent, :bounced]`. If `simulate_error?/0` returns false (e.g. Logger adapter), this test is skipped.

The macro must also require that the using module defines:
- `adapter_module/0` returning the adapter module atom (e.g. `Chimeway.Adapters.Test`)
- `sample_delivery/0` returning a `%Chimeway.Delivery{}` struct suitable for passing to `deliver/2`

Document that future adapters must also `use Chimeway.Adapter.ContractTest` and pass all non-conditional contract tests before being added to the adapters directory.</action>
  <verify>rg "defmacro __using__" test/support/chimeway/adapter/contract_test.ex && rg "function_exported\|:erlang" test/support/chimeway/adapter/contract_test.ex && rg "password.*token.*secret.*api_key\|redact" test/support/chimeway/adapter/contract_test.ex && mix compile --warnings-as-errors</verify>
  <acceptance_criteria>
    - use Chimeway.Adapter.ContractTest injects at minimum 3 tests into the including module
    - Redaction test explicitly checks for keys: password, token, secret, api_key, auth
    - Redaction assertion would fail if the adapter returns meta containing a key named :token
    - Contract tests are isolated: they do not share state across test cases
    - The module compiles and loads in the test environment without warnings
    - adapter_module/0 and sample_delivery/0 are required callbacks (the macro raises if not provided)
  </acceptance_criteria>
  <done>Shared contract module exists, compiles, and injects testable assertions when used by any adapter test.</done>
