## User Constraints (from CONTEXT.md)

### Locked Decisions

### Atom-safe metadata parser
- **D-01:** Replace `:file.consult/1` with a small private, in-memory, byte-oriented parser for the canonical Hex metadata subset. Archive-controlled bytes must never reach `:file.consult/1`, `:erl_scan`, `:erl_parse`, `Code.string_to_quoted`, `String.to_atom/1`, `List.to_atom/1`, or any evaluator or atom-creating conversion.
- **D-02:** Parse repeated dot-terminated `{binary_key, value}.` forms and materialize only the binary-keyed `<<"name">>`, `<<"version">>`, and `<<"files">>` fields. Recognize only the fixed literals required by the Hex grammar, such as `true` and `false`, without deriving atoms from input.
- **D-03:** Allow unknown binary-keyed fields only when their values are structurally valid under the safe bounded grammar. Reject arbitrary bare or quoted atoms, variables, expressions, improper lists, duplicate selected keys, malformed delimiters or escapes, trailing content, and unsupported constructs. Atom-looking content inside binaries remains ordinary valid data.
- **D-04:** Bound total parser work: reject metadata above 1 MiB before scanning, cap nesting depth at 32, cap `files` entries at the existing 4,096-member budget, cap `name` and `version` at 255 bytes, and keep scanning linear in input size. Parse the already-bounded binary without a temporary metadata file.

### Valid archive compatibility and trust semantics
- **D-05:** Preserve successful validation of real `mix hex.build` archives and the existing production-shaped fixtures. Keep exact package name `chimeway`, bounded valid version handling, required runner/fixture membership, regular-file presence, supported artifact-root layouts, and version agreement with unpacked `mix.exs`.
- **D-06:** Reject duplicate `name`, `version`, or `files` fields rather than silently choosing a winner. Invoke the callback exactly once and only after digest, metadata, extraction, root, required-file, and version validation all succeed.
- **D-07:** Continue treating a caller-supplied digest as integrity only, never publisher authenticity or trust, because the caller supplies both archive and digest. Preserve the existing immutable-byte validation order and do not introduce trusted-package language.
- **D-08:** Keep the compatibility promise narrow: support archives produced for Chimeway's proof path, guarded by a real-build contract. Do not create a general Erlang-term or universal Hex metadata library and do not add `hex_core` solely for this private proof seam.

### Executable security evidence
- **D-09:** Add a direct synchronous release-gate regression using a correctly digested hostile archive. Warm the parser path, generate randomized atom-token strings without interning them, record `:erlang.system_info(:atom_count)`, assert validation rejection and callback non-invocation, assert exact atom-count equality, and confirm sampled tokens still fail `String.to_existing_atom/1`.
- **D-10:** Cover bare atoms, quoted atoms, variables, atom-looking binary contents, duplicate selected fields, oversized metadata, excessive nesting and file counts, malformed/trailing syntax, and the real Hex-built success path. Use hundreds rather than thousands of hostile tokens so the initial red test demonstrates the vulnerability without needlessly risking the test VM.
- **D-11:** Route objective acceptance through `mix ci.verify_gates` and the affected ecosystem `verify.*` jobs. This security closure receives executable evidence, not conversational UAT.

### Developer experience and scope discipline
- **D-12:** Keep `with_validated_archive/3` and both existing callers behaviorally stable. Failures remain concise and sanitized; never echo archive metadata, hostile tokens, parser excerpts, temporary paths, raw exceptions, or terminal-control bytes. Internal closed reason categories may remain private implementation details.
- **D-13:** Keep the Phase 96 cold-subprocess timeout warning outside this phase because the atom-safety regression is in-process. Permit only the smallest timeout repair if the existing warning blocks the required green release gate; do not undertake general subprocess or CI restructuring.
- **D-14:** No Phoenix, Plug, Ecto, database, telemetry, browser UI, visual design, documentation-information-architecture, or public API change belongs in this phase. The adopter-facing result should be deliberately boring: the same command and proof output work, while hostile archives fail before callback execution without mutating the VM.

## Summary

The release blocker is real and tightly scoped: `ArtifactArchive.with_validated_archive/3` hashes the archive, obtains `metadata.config` from the in-memory outer tar, and then sends archive-owned bytes through `parse_metadata!/1`, which writes a temporary file and calls `:file.consult/1`. The existing binary-key allowlist executes only afterward, so it cannot reverse atom interning. [VERIFIED: codebase inspection] Erlang documents that atoms are never garbage-collected and that converting arbitrary input to atoms risks a denial of service. [CITED: https://www.erlang.org/doc/system/commoncaveats.html]

Hex’s package specification defines metadata as an Erlang-term file, uses UTF-8 binaries as strings, and includes booleans, lists, and key/value lists; `name`, `version`, and `files` are required. [CITED: https://github.com/hexpm/specifications/blob/main/package_metadata.md] Chimeway only needs those three binary-keyed semantic fields, so a private bounded grammar is both smaller than a general term parser and compatible with its proof boundary. [VERIFIED: codebase inspection]

**Primary recommendation:** Replace only `parse_metadata!/1` with a private byte-oriented recursive-descent/state-machine parser that returns `%{<<"name">> => binary, <<"version">> => binary, <<"files">> => [binary]}` after validating all terms, and extend the existing release-gate contract test builders for real-archive and atom-count evidence. [VERIFIED: codebase inspection]

### Pattern 1: Fixed-token, binary-only recursive descent

**What:** Advance a binary cursor over whitespace, punctuation, `<<...>>` binary literals, proper lists, tuple pairs, fixed `true`/`false`, numbers only if needed for unknown valid metadata, and nested binary-keyed tuples; return binary strings and fixed internal values only. [VERIFIED: 96.1-CONTEXT.md]

**When to use:** For `metadata.config` after its byte-size check and before any materialization or callback. [VERIFIED: codebase inspection]

**Example:**

```elixir
# Source: Phase 96.1 locked D-01..D-04 (implementation shape, not a general Erlang parser)
defp parse_metadata!(metadata) when byte_size(metadata) <= @max_metadata_bytes do
  {config, <<>>} = parse_forms(skip_ws(metadata), %{selected: %{}, depth: 0})
  config
end

defp selected_field!(<<"name">>, value, state) when is_binary(value),
  do: put_unique_selected!(state, <<"name">>, value)
defp selected_field!(key, _value, state) when is_binary(key), do: state
```

The implementation must not call a parser/evaluator or atom conversion on untrusted bytes. [VERIFIED: 96.1-CONTEXT.md]

### Pattern 2: Prove non-mutation at the VM boundary

**What:** Warm the parser before measuring, create hundreds of unique candidate atom spellings as binaries, validate a correctly digested hostile archive synchronously, then require `atom_count` equality and `String.to_existing_atom/1` failure for sampled candidates. [VERIFIED: 96.1-CONTEXT.md]

**When to use:** As the direct regression that closes ARCHIVE-ATOM-01; do not outsource it to a subprocess where a new VM masks atom-table mutation. [VERIFIED: 96.1-CONTEXT.md]

### Anti-Patterns to Avoid

- **Temporary file plus `:file.consult/1`:** It parses arbitrary archive-owned Erlang terms before validation and can intern atoms. [VERIFIED: codebase inspection; CITED: https://www.erlang.org/doc/system/commoncaveats.html]
- **`Map.new(terms)` after general parsing:** It cannot distinguish duplicate required keys once duplicates have been collapsed; reject them while parsing. [VERIFIED: codebase inspection; 96.1-CONTEXT.md]
- **A permissive “skip unknown text” branch:** Unknown fields must still be structurally valid, bounded grammar values; otherwise valid-looking prefixes can conceal unsafe syntax. [VERIFIED: 96.1-CONTEXT.md]
- **Returning raw parse errors:** The public CLI contract emits one fixed error and must not reveal hostile metadata, paths, tokens, or exceptions. [VERIFIED: codebase inspection; 96.1-CONTEXT.md]

## Common Pitfalls

### Pitfall 1: Atom safety test accidentally interns its own sample
**What goes wrong:** Constructing hostile names with atom syntax, interpolation into atom literals, or `String.to_atom/1` in test setup invalidates the proof. [VERIFIED: 96.1-CONTEXT.md]
**Why it happens:** Atom-count testing observes global VM state. [CITED: https://www.erlang.org/doc/system/commoncaveats.html]
**How to avoid:** Generate token spellings as binaries/strings only, warm parser code before the baseline, use exact equality, and verify samples with `String.to_existing_atom/1`. [VERIFIED: 96.1-CONTEXT.md]
**Warning signs:** Baseline and final count differ before validation, or an asserted existing-atom failure succeeds. [VERIFIED: 96.1-CONTEXT.md]

### Pitfall 2: Compatibility is tested only with synthetic metadata
**What goes wrong:** A narrow parser passes hand-written fixtures but rejects the canonical fields emitted by the project’s current Hex build. [VERIFIED: 96.1-CONTEXT.md]
**How to avoid:** Keep the current `mix hex.build` archive contract and prove callback success with it, alongside production-shaped builders. [VERIFIED: codebase inspection; 96.1-CONTEXT.md]

### Pitfall 3: Bounded grammar has unbounded work or state
**What goes wrong:** Deep values, huge string fields, files lists, or repeated concatenation cause resource exhaustion despite atom safety. [VERIFIED: 96.1-CONTEXT.md]
**How to avoid:** Enforce the locked 1 MiB, depth 32, 4,096 files, and 255-byte name/version limits during cursor advancement; prepend/reverse list accumulators rather than repeated `++`. [VERIFIED: 96.1-CONTEXT.md; CITED: https://www.erlang.org/doc/system/commoncaveats.html]
