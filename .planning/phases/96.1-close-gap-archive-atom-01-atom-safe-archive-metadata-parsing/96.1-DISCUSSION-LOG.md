## Expanded Research Applied

Three parallel research tracks were synthesized:

1. **Elixir/OTP/Hex parser design** — compared a local bounded parser, `hex_core`, lexical preflight plus `:file.consult/1`, alternate manifests, and `:erl_scan`/`:erl_parse`. Ranked the local bounded parser first and used current Hex's bounded safe scanner as a reference design.
2. **Cross-ecosystem archive security** — applied lessons from Hex, RubyGems, Go modules, Python wheels, npm/node-tar, Cargo, Maven, and Apache Commons Compress: integrity is not trust; validate before materializing; bound total work; parse only needed metadata; reject ambiguity; keep errors non-injectable and non-sensitive.
3. **Chimeway architecture and DX** — applied project methodology, Phase 93–96 contracts, prompt/brand guidance, release-gate parity, and the consumer JTBD. Confirmed that no visual UI work applies; the relevant UX is stable commands, sanitized failures, no new dependency/configuration, and executable evidence.

## Recommendation Convergence

- Implement one private byte-oriented parser with a 1 MiB metadata cap, depth 32, 4,096 file-entry limit, and selective retention of `name`, `version`, and `files`.
- Permit unknown binary-key fields only within the safe grammar; reject arbitrary atoms, variables, expressions, duplicates, unsupported syntax, and trailing data.
- Keep callers and success output unchanged; treat digest as integrity only.
- Prove exact atom-count stability and callback non-invocation using a correctly digested hostile archive, while retaining real `mix hex.build` acceptance.
- Defer general archive redesign, authenticity, new manifests, public APIs, UI, and unrelated subprocess performance work.

The user approved this complete recommendation set without correction.
