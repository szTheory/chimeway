<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| trigger transaction -> workflow state rows | One request inserts durable notifications and workflow runs atomically. |
| workflow transition writer -> operator history | Append-only reasons become the source of truth for later journey inspection. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-24-04 | T | `Chimeway.Trigger` workflow creation path | mitigate | Keep definition lookup, notification insert, run creation, and transition insert in one `Ecto.Multi` so partial workflow state cannot commit. |
| T-24-05 | R | `workflow_transitions` | mitigate | Persist exact reason strings and linked step ids on every initial transition so operators do not infer state from timestamps or queue artifacts. |
| T-24-06 | D | `workflow_runs` uniqueness | mitigate | Enforce one run per notification with a unique database index on `notification_id` and query reuse helpers in `Chimeway.Workflows`. |
</threat_model>
