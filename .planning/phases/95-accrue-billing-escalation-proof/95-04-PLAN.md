<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CLI arguments -> filesystem/archive operations | Caller paths and digests are untrusted and must never widen cleanup scope. |
| Package archive -> unpacked executable | Archive bytes, metadata, manifest, and extracted paths must agree before code is loaded. |
| Packaged runner -> generated consumer | Only the validated, newly unpacked artifact may become the consumer's Chimeway dependency. |
| Failed subprocess -> diagnostics | Raw output may contain filesystem, DB, or fixture details and must be reduced to safe categories. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-95-18 | Spoofing | archive provenance | high | mitigate | Task 1 validates archive SHA-256, Hex metadata name/version/files, and uses only its fresh unpack result. |
| T-95-19 | Tampering | archive extraction | high | mitigate | Task 1 requires one contained artifact root and manifest membership before loading packaged support. |
| T-95-20 | Elevation of Privilege | cleanup paths | high | mitigate | Task 2 confines all deletion to registered fixture identities and runner-owned temporary roots. |
| T-95-21 | Information Disclosure | CLI stderr | high | mitigate | Task 2 asserts sanitized category-level errors and zero proof lines on every failure. |
| T-95-22 | Denial of Service | orphaned PostgreSQL/filesystem resources | medium | mitigate | Tasks 1-2 use nested try/after cleanup and execute controlled failure contracts. |
| T-95-23 | Repudiation | package command availability | medium | mitigate | Task 1 inspects built metadata then invokes the exact packaged path in an OS process. |
</threat_model>
