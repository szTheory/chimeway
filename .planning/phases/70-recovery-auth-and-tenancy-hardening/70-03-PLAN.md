<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| Public Chimeway recovery APIs to core Deliveries | Host/admin callers pass opts that may include safe evidence and unsafe unknown values. |
| Core recovery APIs to database | Recovery metadata becomes durable evidence on canonical rows. |
| Core recovery to dispatcher | Duplicate or stale submits must not dispatch duplicate work. |
| Recovery metadata to traces | Trace projection must expose only safe recovery facts. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|---|---|---|---|---|
| T-70-03-01 | Tampering / Repudiation | Duplicate or stale recovery submit | mitigate | Preserve atomic `begin_recovery/2` recovered_at guard and add tests that duplicate/stale attempts return `{:noop, ...}` without duplicate dispatch. |
| T-70-03-02 | Information Disclosure | Unknown or unsafe opts become durable metadata | mitigate | Allowlist only source, reason, recovered_at, recovery_actor_ref, and recovery_confirmation_marker; tests assert forbidden raw keys/values are absent. |
| T-70-03-03 | Repudiation | Recovery lacks durable operator evidence | mitigate | Persist safe actor reference and confirmation marker when supplied, preserving existing source/reason/recovered_at behavior. |
| T-70-03-04 | Information Disclosure | Trace projection leaks raw recovery inputs | mitigate | `test/chimeway/traces_test.exs` asserts trace evidence includes safe recovery facts and excludes raw session, params, payload, provider, token, auth code, authorization, and PII values. |
| T-70-03-SC | Tampering | Package manager installs | accept | No dependency install is planned. |
</threat_model>
