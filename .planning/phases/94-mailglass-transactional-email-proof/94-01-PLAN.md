<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| generated consumer output -> release-gate parser | Subprocess text is untrusted and must match one complete fixed allowlist without atom creation. |
| repository -> unpacked artifact consumer | The proof must reject source-tree substitution and retain artifact-only provenance. |
| generated host -> Mailglass Fake state | Shared in-process transport state requires explicit ownership and serialized execution. |
| public trace -> CI log | Only stable explanation fields may cross; message, recipient, credential, provider, and metadata content stays private. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-94-01 | Tampering | generated consumer `:chimeway` dependency | high | mitigate | Preserve `validate_artifact_dependency!/3` and contract-test rejection of repository-root/source-tree paths before commands run. |
| T-94-02 | Information Disclosure | `CHIMEWAY_MAILGLASS_PROOF` serializer/parser | high | mitigate | Serialize from one public explanation into an exact allowlist; reject extra/duplicate/malformed fields and contract-test every sensitive category. |
| T-94-03 | Tampering | Mailglass Fake process ownership | medium | mitigate | Call `checkout/0` and `set_shared(self())` before trigger and keep the proof `async: false`. |
| T-94-04 | Denial of Service | temporary database/filesystem lifecycle | medium | mitigate | Reuse unique identities, command timeouts, and success/rescue/catch cleanup with explicit failure-path contracts. |
| T-94-05 | Spoofing | generic adapter success masquerading as Mailglass composition | high | mitigate | Assert exact persisted render identity, configured host mailable function, one Fake record, Mailglass adapter module, and succeeded public attempt. |
</threat_model>
