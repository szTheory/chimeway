<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| delivery state query -> operator recovery actions | Recovery must only target rows Chimeway can prove are stuck from durable state |
| concurrent recovery attempts -> canonical delivery row | Multiple operators or jobs must not both claim the same row as recoverable |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-22-01 | T | `lib/chimeway/deliveries.ex` | mitigate | Use a guarded state predicate and one-row update boundary so only still-recoverable rows accept recovery metadata. |
| T-22-02 | R | delivery metadata recovery facts | mitigate | Persist exact `recovery_source`, `recovery_reason`, and `recovered_at` values on the canonical row for later explanation. |
| T-22-03 | D | recoverable-row query | mitigate | Exclude deferred, dispatched, and terminal rows so recovery cannot fight active lifecycle transitions. |
</threat_model>
