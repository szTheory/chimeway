<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator recovery action -> delivery mutation | A manual or automated recovery request changes canonical delivery-row metadata |
| delivery recovery helper -> configured dispatcher | Chimeway hands a recovered row back to runtime enqueueing/execution |
| public `Chimeway` API -> host application callers | Recovery actions become callable from IEx, admin tooling, or scripts |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-22-04 | T | `lib/chimeway/deliveries.ex` | mitigate | Update only the existing row under a conditional `update_all` predicate; do not insert replacement deliveries or mutate non-recoverable states. |
| T-22-05 | R | `lib/chimeway/deliveries.ex` | mitigate | Persist durable string-keyed recovery metadata (`recovery_source`, `recovery_reason`, `recovered_at`) on the canonical row before successful handoff. |
| T-22-06 | D | `lib/chimeway/deliveries.ex` | mitigate | Normalize duplicate or late recovery attempts to `{:noop, delivery}` and roll back metadata when dispatcher handoff fails. |
</threat_model>
