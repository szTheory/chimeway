| Boundary | Description |
|----------|-------------|
| operator recovery API -> configured dispatcher | Recovery must use the canonical dispatch seam instead of inventing a second send path |
| duplicate recovery calls -> active delivery lifecycle | Re-drive attempts must not race into duplicate dispatch or replacement-row creation |

|-----------|----------|-----------|-------------|-----------------|
| T-22-04 | T | `lib/chimeway/deliveries.ex` | mitigate | Route all recovery through `dispatch_delivery/2` on the existing delivery row after a guarded recovery claim. |
| T-22-05 | R | recovery API results | mitigate | Preserve `source`, `reason`, and `recovered_at` facts so later traces can explain that a re-drive happened. |
| T-22-06 | D | duplicate recovery attempts | mitigate | Treat dispatcher skip and post-claim state drift as explicit noop outcomes rather than retrying blindly. |
