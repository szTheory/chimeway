## Stabilization Debt

1. **Trigger error propagation:** `Notifier.resolve_rendering/3` errors can escape the reducer as `FunctionClauseError`. The surrounding transaction rolls back and publishes no hint, so no v1.19 invariant is violated, but the public failure contract is wrong.
2. **Lifecycle/signal atomicity:** the first `seen_at` or `read_at` update commits before `Signal.track/4`; a signal write failure leaves lifecycle truth without workflow progression and cannot heal on replay. This is resilience debt, not a normal-path gap.
3. **Phase 105 coverage seam:** rollback/no-publish is proven through a database failure, but not through the malformed rendering-error path; no single mounted test spans trigger publication through bell refresh.
4. **Detached-doc anti-vacuity:** the verifier confirms required calls exist in the focused test AST, but does not prove they are reachable from a test. The selected proof currently executes the real path.
5. **Documentation metadata:** the inbox guide says callback context is a keyword list although runtime passes a map, retains a stale v1.9 label, and `MAINTAINING.md` understates the aggregate gate's GATE-02 scope.
6. **Planning metadata:** completed Phase 106 and 107 plan checkboxes remain unchecked in the roadmap.

Dependency resolution also reports locked-package security advisories. Those are release-hygiene inputs and not evidence that a v1.19 requirement is unsatisfied.

## Release Decision

Do not add another product phase. Run one bounded stabilization batch for the concrete warnings and repository hygiene, re-run release gates, then complete/archive v1.19 and prepare the release.
